# Competitive improvements for Files Plus, Preview Plus, and Mods Plus

Finish physical acceptance of the current workflows first. The first new work should help people find a file by a partial name, jump to a place in an open document, and see which installed packages require attention. Each can ship independently. Files content search can build on Preview's location handling. New package mutations depend on the separate single-package recovery work. Stock Files click routing depends on an upstream API.

This is a proposal dated 2026-11-23. Repository source was inspected at remote `main` [`9d8e017`](https://github.com/linziyanleo/herdr-mods/commit/9d8e0172da18902b18650951fe3f187e19964334). Feature observations are from source and published documentation. The [November 16 implementation report](interaction-performance-implementation.md) contains the earlier measurements, test results, and native acceptance record.

## Files Plus

### What the alternatives show

- Quick Open solves “I remember a few letters and want the file next to my terminal.” It ranks by basename and word starts, supports smart case and slash queries, keeps recents per machine and root, caches a bounded file list, and yields between scoring batches. Enter pastes, Cmd+Enter opens an in-Herdr viewer, and Shift+Enter opens a local editor. Its local and remote enumeration uses POSIX `sh`, with Git and `rg`, `fd`, or `find` paths. It includes hidden and ignored files with a lower rank and common excluded trees. Files Plus already has the captured `@` action, native result rows, and multi-root routing. Its search currently requires every query term to occur in the relative path, starts a fresh traversal for a changed query, and caps results at 200. Adopt ranking and scoped recents. Keep the existing open and paste semantics. [Quick Open source, 2026-11-16](https://github.com/ReidenXerx/herdr-quick-open/tree/02fb718cbec5840e6e5a0294ef2f361d377f673a/mods/quick-open).
- Workbench solves “find the use of a symbol and see the file without leaving my terminals.” Its separate Search uses ripgrep, Git grep, or grep with case, word, and regex controls, and hands the result's line to its editor. Its README records that it displays the line number without jumping there. It also ships multi-select and file operations, remote tar streaming through `hc exec`, and its own terminal and editor layout. Files Plus needs content search and a reliable result handoff to compete on that workflow. Adopting the whole layout, source-control panel, or transfer helpers would add different state, dependencies, and installation work. [Workbench search and I/O, 2026-11-02](https://github.com/yama-lei/herdr-editor-layout/tree/5220dcde4734331f93db98698d0506ac1b004284/mods/activity).
- Filer Pro solves “browse a server and know what happened to the file.” It exposes Up, Show as Root, Back to terminal, editor actions, transfer progress, and visible limits. The Mac client uses POSIX, native Apple helpers, and separate SSH and SCP paths for connected Linux or macOS hosts. Its default timer is off for quiet remote browsing. Files Plus already follows a terminal, supports an independent local folder, and performs same-machine file actions. Adopt clear root and machine provenance and explicit recovery from an incomplete listing. Defer transfer, remote editing, editor-specific SSH integrations, archive handling, and a different polling policy until there is a verified need and platform design. [Filer Pro guide, 2026-11-11](https://github.com/Srv-02/herdr-filerpro/blob/23427546a27b3d6f1e14ef6f108c0dd8d1ab37b3/docs/GUIDE.md), [transfer source](https://github.com/Srv-02/herdr-filerpro/blob/23427546a27b3d6f1e14ef6f108c0dd8d1ab37b3/mods/filer-pro/bin/transfer.sh).
- dppalomar's Multi-Roots solves “which declared folder should this terminal or agent start in?” It ships saved workspace creation and reopening, root chips for its launch menu, tagged root rows, and a Changes repository selector. It uses the same `.herdr-workspace.json` convention and persisted `multi-root.spaces` family of keys. The fork's workspace mode is local POSIX. Files Plus already has workspace lookup, Add folder, browsing overrides, and New terminal here. Use root-aware labels and targets in search. Defer launcher and Changes integration until demand warrants layout changes. Fold agent context into the existing PR #9 work. [Multi-Roots recipe and source, 2026-11-01](https://github.com/dppalomar/herdr-mods/tree/089d87d6c5651f9950c68d10612cd8462058b83b/multi-root).

### P1 · Rank the existing file search

Start in the existing focused Files search. Rank obvious exact and basename matches ahead of fuzzy matches and preserve multi-term path matching. Show the root and relative path when names collide. Optionally show a small list of recently opened files when search is invoked with an empty query. Scope any recents and reusable inventory to the machine and exact browsing or workspace roots, cap them, invalidate on context or relevant file changes, and keep path inventory in memory. Persist recents only if that behavior is explicitly chosen. Keep result identity and the existing open, preview, pin, and `@` routing. Evaluate a palette entry after the inline flow works, with a user-selected binding only.

Use the current listing path first, including Windows PowerShell and remote POSIX handling. Rank within a bounded candidate scan before applying the display cap so early enumeration order cannot displace a better match in the scanned set. Disclose a partial scan. If a warm inventory or optional faster enumerator is needed, measure it against the same fixture, preserve the current listing policy, and keep a working fallback with no new required binary. Avoid indexing an entire home directory or expanding hidden or ignored traversal by default.

Minimum check: fixture with duplicate names in two roots, fuzzy initials, path terms, Unicode, separators and spaces, an unavailable root, and a large tree. Exercise fast query replacement and a switch to a same-path root on another machine. A deleted recent must fail clearly. Measure cold query, next query, and remote request count against `9d8e017` on the same fixture. Confirm Enter, F6, and F7 still select the expected target and preserve the pinned view.

### P2 · Search file contents and open a specific match

Add an explicit content mode for “find the occurrence across my declared roots.” Start with literal matching and bounded grouped excerpts, including root, machine, line, and column. For Git-aware enumeration, useful diagnostics and binary exclusion, prefer optional `rg --json` on the owning machine. Pass search input as data. Bound output, execution time, files, matches, and outstanding work. Surface unavailable tools and partial results without blocking filename search. Add case, word, and regex controls only after the literal path is validated. Defer workspace-wide replace and background indexing. Use Preview's P1 location request and preserve the current file placement and deduplication rules.

Minimum check: same-name files and repeated hits, excluded and binary files, missing `rg`, metacharacters as literal data, Unicode and CRLF positions, a slow superseded search, and a changed file between search and open. A dirty or pinned target must survive. Verify local native focus first, then one connected POSIX target and a supported local Windows path before claiming those combinations.

A later folder-navigation change can offer an explicit Up or Use this folder action after users show a need. It should use the existing browse override and its return action. Keep declared roots, terminal cwd, and workspace configuration intact. Validate nested and missing roots and cancellation in two spaces. Remote folder selection needs a separate remote browser contract.

### P1 · Jump to a line and find text in Source

Implement Go to line and column first, both interactively and as an optional location attached to an explicit open request. Route it to a reused viewer as well as a newly opened target. Apply the location once to the matching file, machine, and request after the native editor is ready. A reused pane must not move to a stale result or discard an existing draft. If a pinned slot contains another file, use the existing placement or refusal behavior. Start with source view. Preview heading anchors and structured visual viewers keep their own navigation.

Add a small in-file literal find control over the retained source buffer with next, previous, and match count. Use the installed host's selection offsets and validate scrolling to the active match in the real editor. Expose the control in the toolbar or via a view-local command until native key capture is shown to work. Use bounded matches and the displayed text for read-only or truncated documents, with a visible partial-source state. An implementation that remounts `EditorState` on each keystroke would lose selection or undo state. Leave multi-match decoration and replacement for a separate decision if the native API needs a second editor view.

Minimum check: Unicode and CRLF offsets, empty and out-of-range coordinates, zero matches and wrap-around, draft text differing from disk, fixed and paired modes, read-only remote source, and slow A → B → A. Check that a Files match targeting a changed line is disclosed rather than used as a precise selection. Physically confirm native scroll, focus return, IME, Save, undo, and F6/F7/F8 on 0.1.16.

### P2 · Test another local PDF backend and an explicit passage reference

- Prototype Linux paging with optional `pdfinfo` and `pdftoppm`, the same bounded page raster and cache behavior, and a clear missing-tool state. Retain macOS PDFKit. Evaluate Windows native PDF rendering only after a separate platform spike confirms PowerShell and renderer availability. Each support claim needs a native isolated run against multi-page, locked, corrupt, oversized and changing local files, with missing dependencies and page, zoom, and pan behavior exercised. Keep remote media under the separate boundaries below.
- If people need finer references than a file path, offer a deliberate copy of the source path and selected line range first. Consider an explicit, bounded paste of the range and selected text only after confirming the destination and that the person can see what will be pasted. Reuse destination checks from Files. Test dirty-buffer labeling, CRLF and Unicode range calculation, empty selection, a closed or different-machine terminal, and no automatic submission. This operates on selected document text. Workspace composition delivery remains in PR #9.

## Cross-machine and host limits

- The November 23 [official release manifest](https://releases.herdr.dev/app/latest.json) advertised Herdr 0.1.16 with minimum core 0.1.11. The local binaries reported Herdr 0.1.16 and core 0.1.21. Retain Herdr 0.1.16 as the mod floor for the first stages. Releases cover Apple Silicon macOS, x86-64 and ARM64 Linux, and x86-64 Windows. Linux needs a working desktop and Vulkan. A release target provides no evidence that a shell tool, PDF renderer, or mod helper works there. Check the target's installed `herdr.d.ts` and generated `gpui-kit.d.ts`. [Official downloads](https://herdr.dev/download/), [0.1.16 mod API](https://github.com/herdrdev/herdr-app/blob/v0.1.16/defaults/herdr.d.ts), [GPUI type generation](https://github.com/herdrdev/herdr-app/blob/v0.1.16/src/mods.rs#L84-L85).
- A path belongs to its machine. Carry the captured `space`, machine, path, and when relevant terminal/session through asynchronous work. `readTextFile(path, { on })` reads up to 1 MiB of UTF-8 from the chosen host. Expected-content `writeTextFile`, folder picking, and native folder watches are local. On Linux watches skip Git-ignored directories and reject trees above 4,096 eligible directories. macOS and Windows watch recursively, including ignored folders. The host limits pending watched folders to 64. Use cancellation and the existing bounded remote polling, with explicit offline state. `exec` can target a machine, has an 8 MiB output limit, and exposes a timeout without a promise cancellation API. Ignore late work by ownership and use the target's tools and path rules. `window().platform` describes the client. [App mod guide](https://github.com/herdrdev/herdr-app/blob/v0.1.16/docs/mods.md), [generated API](https://github.com/herdrdev/herdr-app/blob/v0.1.16/defaults/herdr.d.ts).
- The desktop stores installed mods, layouts, keys, preferences, shared state, and caches in its local app home. Machine layout documents and terminals live in core. Cross-machine core access supplies remote commands and documented text read/edit/write and terminal-targeted upload. It does not provide a portable mod API for arbitrary binary download, remote folder picking, or atomic remote writes with the same Preview snapshot contract. Native file drag may transfer a local file to a remote terminal. It refuses a directory or a remote path dropped on a different machine. Keep drag separate from `@` insertion and remote media. Core can use SSH or a custom transport. Windows SSH setup depends on keys or an SSH agent, and older remote cores can affect transfer behavior. [App storage and trust](https://github.com/herdrdev/herdr-app/blob/317e673f1f1568b876cbaa0b41dabeb9153ecbea/docs/security.md), [installed guide at 0.1.16](https://github.com/herdrdev/herdr-app/blob/v0.1.16/defaults/AGENTS.md), [core machine documentation](https://github.com/herdrdev/herdr-core/blob/300a455b8cfa91f8f068b49bb9d78b94d3bd4f0e/docs/machines.md).
- Files Plus and Preview Plus currently choose PowerShell for local Windows directory operations and POSIX `sh` for other listings, including remote targets. Saved workspace mode is local POSIX. ## Conditional stock Files integration

[herdr-app #1338](https://github.com/herdrdev/herdr-app/issues/1338) opened November 22 and was open without comments at the November 23 check. It asks stock Files to offer a file click, including its machine, to layout-selected link handlers, with inline preview as the fallback. The proposed outcome would let an opted-in layout route file clicks to a viewer without carrying a clone of the bundled Files source. [PR #1203](https://github.com/herdrdev/herdr-app/pull/1203), merged November 18, deals with modified clicks on terminal links. At checked upstream `master` `317e673`, the type's source is a terminal context and stock Files still calls its own `show(path)`. The release manifest supplies 0.1.16, whose generated API lacks that terminal handler contract. An upstream merge and a shipped API are separate evidence. [Upstream link type](https://github.com/herdrdev/herdr-app/blob/317e673f1f1568b876cbaa0b41dabeb9153ecbea/defaults/herdr.d.ts), [stock Files row source](https://github.com/herdrdev/herdr-app/blob/317e673f1f1568b876cbaa0b41dabeb9153ecbea/defaults/mods/files/main.js).

P3 is an optional adapter after a released host documents stock Files click routing with source identity, machine, and fallback. Route a supported file to the same open and reuse behavior through an explicitly selected personal layout. Continue offering Files Plus for its workspace, search, and file-management behavior. Keep older hosts on their current paths. Minimum check: stock inline preview with no handler or a pass, ordered handlers, an already-open local tab, equal paths on different machines, an offline host, dirty and pinned viewers, and an opt-in layout that preserves its other bindings. A terminal-link adapter may be useful independently if there is demand for it. It cannot stand in for the Files click hook.

## Implementation order and evidence

- P0 records the physical baseline checks and the acceptance owned by the parallel tasks. It gives reviewers a reproducible starting point for changes to focus, data ownership, and package state.
- P1 can proceed in separate reviews. Files ranks file names, Preview owns location and in-file finding, and Mods Plus shows installed status. Keep native interactions scoped to the view and retain current defaults for everyone else.
- P2 adds literal content search after the location contract is verified, and allows independent reviews of local PDF portability and explicit passage references. Mods Plus review cues can proceed independently. Controls based on recovery wait for the package recovery result.
- P3 contains upstream and platform probes. Pick stock Files routing only after a documented release. Pick remote transfer, Windows package mutations, or wider file formats only after a concrete workflow and platform check justify the added dependencies and state.

For each implementation, use the existing Node or Python suite to cover the named regression and run `herdr-app check` for each changed runtime mod in a disposable app home. Use a separate core and only synthetic fixtures for package and clipboard checks. Native load checks cover initial render. Exercise deferred UI, platform tools, and physical input in the appropriate isolated window and capture screenshots for UI changes. Record the app, core, and OS versions and the tests actually run. For performance work, record the workload and separate helper, transport, render, and presentation measurements. Link external designs as references.
